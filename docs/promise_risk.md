# 交付承诺分析

`b2b_reorder_network.promise_risk` 只做批量分析，不改变原有返单流程，也不会下单。
它回答的问题是：**在采购截止日之前，能否交齐所需数量**。这与“每家供应商各自
准时率的平均或乘积”不是同一件事。

## 运行

```bash
python3 -m b2b_reorder_network.promise_risk fixtures/promise_risk.json --output /tmp/promise-risk
```

输出：

- `report.json`：完整结果，包括承诺口径、生存估计、共同线路、验证与方案比较。
- `summary.md`：给采购主管看的摘要。
- `supplier_commitments.csv`：单供应商在不同数量上的交齐概率。
- `plan_comparison.csv`：所有可行拆单方案的整批风险、期望短缺与业务损失。

原有入口和数据库不受影响：

```bash
python3 -m b2b_reorder_network.dispatch.cli fixtures/demo.json --database /tmp/demo.sqlite3
```

## 方法摘要

1. **承诺口径**
   - 原承诺：`contract.promised_at` 始终保留。
   - 生效承诺：双方接受（`accepted: true`）且按 `known_at` 已可见的最后一次改约；
     被拒绝的改约不改变承诺。
   - 两套口径分别输出标签，能看出最后延期把多少“迟到”改写成“准时”，
     但不抹掉原承诺。
2. **结局标签**
   - `on_time_complete` / `late_complete`：签收累计达到目标数量，且在原承诺或
     接受后承诺之前/之后。
   - `terminated`：终止，不是送达。
   - `overdue_unresolved` / `open_not_due`：未结案，均视为未完成观察。
3. **生存估计**
   - 主模型：离散时间 Aalen-Johansen，终止与“看满截止日仍未交齐”是竞争事件。
   - 基准：Kaplan-Meier（把终止当删失）、已结案比例（丢掉未结案）、全样本一律
     视为未交齐。
   - 超过历史单笔观察数量的分配按最后一点外推，报告中标注
     `extrapolated_beyond_observed_scale`，不当作已验证概率。
4. **整批风险**
   - 单供应商概率按分配数量计算；整批“全部交齐”用线路内联合分布。
   - 同线路使用高斯 copula，相关系数由同日、同品类匹配订单组估计；没有匹配组
     或样本不足时明确标为假设。
   - 线路之间默认独立，并说明这是假设。
   - 同时给出“全部交齐”和“全部短缺”两个联合概率；简单平均与独立乘积只作为
     反例对照。
5. **方案比较**
   - 枚举满足最小起订量与产能约束的分配。
   - 同时报告整批交齐（共同线路 / 独立）、同时短缺、截止日前期望交付、期望
     短缺和业务损失。
   - 主推荐按共同线路假设下的期望业务损失选择；不同决策规则可能改变推荐，
     报告中逐条解释。
6. **向前验证**
   - 起点来自 `validation_origins`，只用 `known_at <= 起点` 的数据训练。
   - 标签要求截止日已被完整观察到；终止和已过期未结案记为未交齐。
   - 与基准比较校准（Brier、对数损失、ECE）和业务损失；验证点少时明确提示
     差异可能只是噪声。
   - 模型替换门槛：只有 Kaplan-Meier 基准的对数损失低出 0.05 以上才替换主模型；
     否则保留竞争风险模型，避免追逐验证噪声。
   - 期望业务成本按“承诺 vs 准备替代资源”的较优行动计算，并与“一律承诺 /
     一律准备替代”两个极端对照。
7. **保留意见**
   - 历史未覆盖的品类或规模返回 `insufficient_support`，不给成功概率。
   - 产能、最小起订量、非历史分配规模、业务损失参数都会单独提醒。

## 业务损失参数

以下参数是显式假设，采购主管可以按合同替换：

- `shortage_cost_per_unit = 20`：短缺每件损失。
- `simultaneous_disruption_cost_per_unit = 8`：同线路同时中断的额外准备成本。
- `hedge_cost_per_unit = 6`：准备替代资源的每件成本。
- `commit_threshold = 0.8`：整批交齐概率低于该阈值时不建议承诺全部按期。

## 不在范围内

- 不写数据库、不改原有 saga、不下单。
- 不做供应商选择以外的议价、合同或价格优化。
- 不在没有历史覆盖的品类上给出“成功概率”。
